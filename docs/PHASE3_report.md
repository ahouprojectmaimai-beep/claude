# PHASE 3 報告：公式LINE連携（受け口の実装）

- 日付: 2026-10-03
- 状態: **プログラム完成・自動テスト合格／本物のLINEでの動作確認は公式アカウント作成待ち**

## 1. 実装したもの
| 部品 | 内容 |
|---|---|
| Webhook受け口（`src/worker/index.ts`） | LINEからの通知を受け取り、**署名を検証**（偽の通知は拒否）→ 保存 → キューへ。すぐ応答を返す |
| 重複防止 | LINEの `webhookEventId` で同じ通知を二重に処理しない。再送分は後段が冪等なので安全に再投入 |
| 画像の保存（`src/line/handler.ts`） | 受け取った写真を**すぐ自社ストレージ（R2・非公開）へ保存**（LINE側の画像は一定期間で消えるため）。SHA-256 で同じ写真の再送を検出 |
| 店舗名と写真の紐付け | 同じ人が前後10分以内に送った「○○店」と写真を組にする。**写真が先・店名が後でもOK**。別の人の店名とは組にしない |
| 返信 | 正常時は返信しない（グループが騒がしくならない）。店名が複数・同じ写真の再送のときだけ、元の投稿を引用して返信（無料の応答メッセージ） |
| 事務員メッセージ | 「現金チェック」を含むメッセージを、同志社前の現金確認の仕事として積む |
| グループIDの確認 | Botをグループに招待すると、そのグループのIDを返信。「#グループID」と送っても確認できる |
| 動作確認モード | `DEBUG_ACK=true` の間は「📥 受付：白梅町店 写真1枚」と毎回返信（本番前の確認用） |
| 保存先（D1） | `migrations/0001_line.sql`：受信イベント・画像・店名投稿・仕事の各テーブル（一意キーで二重登録防止） |

※ 写真の解析・照合・記録（PHASE 2 の仕組みとの接続）は PHASE 4 で行う。PHASE 3 では「解析の仕事」をDBに積むところまで。

## 2. テスト結果

- 署名検証、店名と写真の紐付け（前後・10分超・別人）、二重処理、同じ写真の再送、店名が複数、事務員メッセージ、他グループの無視、返信失敗時の継続、APIエラー時に本文をログに出さないこと
- Cloudflare Workers 向けのビルド確認（`wrangler deploy --dry-run`）OK

## 3. 残っている問題
1. **本物のLINEでの確認が未実施**（PHASE 1 の調査結果「グループの写真・テキストを受け取れる／グループへ送信できる」を実機で確かめる）

3. 写真を送ったあと「送信取消」された場合の扱いは未対応（PHASE 6 の例外処理で対応）
