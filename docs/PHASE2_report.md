## 1. 実装したもの
| 部品 | 内容 |
|---|---|
| AI読み取り（`src/extraction`） | Claude（claude-opus-5-5）で写真を構造化データに書き写す。読み方の手順が違う2系統（A/B）で独立に読む。他社AI・OCRに差し替え可能な形 |
| 数値化（`src/validation/normalize.ts`） | AIの「書き写した文字」をプログラムで金額・日付に変換。和暦（令和）・西暦2桁・西暦4桁は書類ごとに設定で決める |
| 安全装置（`src/validation`） | ①ボヤけ・隠れ → 判読不能 ②1桁でも自信がない欄 → 判読不能 ③2系統の読み取りが違う → 判読不能 ④通帳の残高検算 ⑤レジ精算票の検算 ⑥店舗名のクロスチェック ⑦日付の範囲チェック |
| 照合エンジン（`src/matching`） | 営業日の翌日の入金を探す／小銭の後日入金を金額で自動振り分け／同志社前の2段階管理／廃油（祝日は次の銀行営業日まで）／二重加算の防止 |
| 事務員メッセージ解析 | 「9/28〜9/30分 現金チェックOK」などをAIを使わずに解析。登録外の人の発言・解釈できない書き方は反映せず要確認 |
| 設定（`config/`） | 店舗ごとの銀行・小銭ルール・レジ精算書式、銀行休業日（2026〜2027年） |
| 確認用コマンド（`scripts/`） | 実画像の解析（APIキー必要）／保存した読み取り結果からの再現 |

## 2. テスト結果
**自動テスト 320件 すべて合格**（型チェックも合格）

| 分類 | 主な確認内容 |
|---|---|
| 金額・日付の変換 | 「65,32」のような曖昧な数字は変換しない、和暦・西暦の解釈 |
| 銀行営業日 | 2026年シルバーウィーク明け、年末年始 |
| 画像の安全装置 | ボヤけ、自信の低い欄、2系統の不一致、検算の不一致、店舗名の食い違い、書式未登録 |
| 白梅町・聖護院 | 一致→OK／小銭不足→要確認（待たない）／営業日と同じ日付の入金は翌日入金と見なさない |
| 京大前・ほりまる | お札のみ→小銭入金待ち→追加入金で完了／期限超過→要確認／連休明けの小銭5行を各営業日へ自動で振り分け／同額の候補が2つ→推測せず要確認 |
| 同志社前 | お札入金OK→事務員の現金チェックOKで最終確認完了／登録外の人の発言は反映しない |
| 廃油 | 祝日回収→次の銀行営業日入金OK／同額2行は「油入金」メモで特定、メモなしは要確認／油入金の行を小銭と取り違えない |
| 重複・再提出 | 同じ投稿の2重処理、同じ写真の再送、ボヤけ→撮り直しでOK |
| **誤読でOKにならないか** | 金額・日付・通帳の全欄について、1桁をあらゆる数字に読み間違えさせて網羅的に確認（約2,000通り）。「本当は合っていない日がOKになる」ケースは0件 |

## 3. テストで見つかり、設計に反映したこと
- **2つのAIが日計表の金額を同じように読み間違えると、検算のない店舗では小銭の残額を誤って記録しうる**（例：小銭が後日入金になる京大前店）。
  → 書式を登録する店舗は、**レジ精算票の検算（金種合計・在高実績−翌準備金など）の設定を必須**にした。未設定ならシステムが起動しない。
- 通帳の1行目（前の行がない行）は残高検算ができないため、照合対象がその行なら要確認になる（新しいページの1行目など）。
